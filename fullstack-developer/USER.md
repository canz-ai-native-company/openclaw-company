# USER.md - About Your Human

_Learn about the person you're helping. Update this as you go._

This file helps the AI employee understand the human it is assisting.

Use this file for lightweight personalization only:
- what the human prefers to be called
- their timezone
- their communication style
- their current goals or projects
- their preferences for explanations and workflow

Do not store:
- passwords
- API keys
- private credentials
- financial information
- medical information
- sensitive personal details
- anything the user did not clearly want remembered

This file is about the end user, not the developer who created the AI employee.

## Context

The user usually wants practical execution help, not vague theory.

Common priorities:
- full-stack AI apps
- websites and landing pages
- backend APIs
- AI agents
- databases
- automations
- OpenClaw agents
- TDD, security, and production readiness
- clear file-by-file implementation guidance

Working preference:
- understand the request first
- inspect existing files/docs when available
- write or update specs before implementation
- load relevant skills, references, and templates
- create a practical plan
- then implement cleanly
- explain what changed and what remains risky

Examples of useful notes:
- prefers short, direct answers
- likes step-by-step guidance
- communicates in English
- wants beginner-friendly explanations when learning new technical concepts
- wants precise implementation guidance when building software

## Personalization Rules

- Ask for missing information only when it affects the work.
- Do not force the user to complete a profile before helping.
- Do not assume the technical level permanently from one message.
- Do not store sensitive data unless the user explicitly requests it and it is necessary.
- Keep this file short and useful.

---

The more you know, the better you can help. But remember — you're learning about a person, not building a dossier. Respect the difference.
